# 功率控制

从 H7_BSP `4c1dbd4` 移植，保持上游 `PowerControl` 接口。模块已注册到根 CMake，
无设备、任务或动态内存依赖；当前未接入 Chassis 控制链，也不自动读取裁判系统或发送电机命令。

## 模型与单位

一个实例处理 1～4 个电机，所有电机使用共同力矩缩放系数 `s ∈ [0,1]`：

```text
P(s) = P_static + k_f × Σ|ω_i| + s × Σmax(τ_i × ω_i, 0) + s² × k_c × Στ_i²
可用预算 = max(power_limit_w - reserve_power_w, 0)
输出力矩 = s × 目标力矩
```

`τ` 是输出轴力矩 N·m，`ω` 是同一轴的角速度 rad/s，功率为 W。
`k_f` 的单位为 W/(rad/s)，`k_c` 为 W/(N·m)²；系数、静态功耗和预留功率需要按机构标定。
制动机械功率不抵扣预算。若静态功耗与摩擦项已经超过预算，输出力矩为零，
`budget_below_baseline` 为 true，估计功率仍可能超过预算；调用方据此决定功能策略。

## 接口与调用顺序

| 接口 | 契约 |
| --- | --- |
| `Init(&config)` | 电机数 1～4，静态功耗/摩擦系数/预留功率非负，铜耗系数大于零；失败保留原配置 |
| `Set_Input(&input)` | 复制本周期目标力矩、速度和功率上限；非法输入使输出清零 |
| `TIM_Calculate_PeriodElapsedCallback()` | 消费一次输入并计算，返回 false 时输出清零；没有新输入不能重复计算旧目标 |
| `Get_Output()` | 返回限幅后力矩、估计功率、缩放系数及预算状态，不发送命令 |
| `Update_Identification(power, torque, speed)` | 对新鲜、时间对齐的实测功率与实际力矩/速度辨识一次，返回是否接受 |
| `Get_Model_Coefficients(&friction, &copper)` | 读取当前实际用于功率预测的损耗系数 |
| `Reset_Identification()` | 将功率预测系数恢复为配置基线，并重置估计器 |

由拥有电机的 Application 保存实例，显式初始化后，在同一控制任务中执行：

1. 完成速度控制计算，将候选电流指令换算为输出轴力矩。
2. 提供同轴速度、有效功率预算，调用 `Set_Input()` 和计算接口，检查两个返回值。
3. 读取限幅力矩并换算回设备控制单位，由原所有者提交命令；计算失败时采用安全输出。
4. 有新功率测量时，再用与该测量对齐的实际力矩及速度更新辨识。

当前 DJI 控制环输出为协议电流值，不能直接填入 `desired_torque_nm`。
四舵轮底盘包含 8 个电机；接入时需明确轮电机、舵电机各自预算，不能让两个实例分别使用整车总预算。
本模块不处理电机在线状态、裁判数据新鲜度、转矩常数、传动效率或积分抗饱和。

## 在线辨识

配置 `enable_rls=true` 时使用 [RLS](../../Middleware/Algorithm/RLS/README.md) 的二维估计器：

```text
features = [Σ|ω_i|, Στ_i²]
measurement = 实测功率 - 静态功耗 - Στ_i × ω_i
parameters = [摩擦系数, 铜耗系数]
```

遗忘因子需在 `(0,1]`，初始协方差大于零；两个系数上限不得低于配置基线。
任一电机制动、测量残差为负、无激励或数值非法时拒绝更新。
候选系数越界时保留当前功率模型并重新初始化估计器；接受后预测系数不低于配置基线。
每帧功率测量最多更新一次，不用目标力矩替代实际力矩，也不重复使用旧测量。

所有接口由单一执行上下文调用，跨任务使用需调用方同步。内部有 double 运算，
接入高频闭环前应在 STM32H723 上测量执行耗时；当前仅完成主机算法验证与固件构建。
